# HANDOFF.md 格式规范

`HANDOFF.md` 是交接包的核心。读者是**对本项目零背景的接手模型**。写它的唯一标准：读完 + 核对 git 现状后，接手模型不需要再问交接文档本可回答的问题。

写作总原则：

1. **具体压倒概括**：写 `src/auth/login.ts:42`，不写"认证模块"。
2. **可执行压倒描述性**：任务条目动词开头，接手模型读完就能动手。
3. **决策必须带 why**：没有理由的决策会在交接后被推翻，返工成本最高。
4. **短**：整篇目标 <400 行。大体积证据进 `attachments/`，正文只留指针。

## 各节写作要求与正反例

### 3. 当前进度

- 每条必须落到**文件/提交/测试结果**这类可验证的锚点。
- 反例：`✅ 完成了登录功能`（接手模型不知道去哪核实）
- 正例：`✅ 登录 API 完成：src/routes/auth.ts 已实现 POST /login，13 个单测全绿（npm test）`

### 4. 任务规划

- 每条：**动词开头 + 目标文件 + 验收方式**。
- 反例：`1. [ ] 完善 UI`（无法执行）
- 正例：`1. [ ] 为登录表单增加错误提示：修改 src/components/LoginForm.tsx，接口失败时展示后端 message 字段`
- 排序原则：阻塞项 > 半成品收尾 > 新功能。

### 5. 关键决策与约束

- 反例：`采用了 JWT 方案`（为什么？换工具后被质疑就得重新讨论）
- 正例：`认证用 JWT（无状态，部署环境无共享存储）；refresh token 不落库，过期 7 天即失效——用户已确认接受此安全模型，不要改成 session 方案`

### 6. 关键文件与代码入口

- 只列接手模型**最先需要看**的 5-10 个文件，多了等于没列。
- 文件路径必须真实存在；**行号写入前必须 `grep -n` 实际核对**，凭记忆写的行号普遍漂移 2-5 行，会直接把接手模型带偏。

### 8. 风险与已知坑

- 只写**本会话中实际发生过**的（报错、误判、返工）或**用户明确提醒**的。
- 反例：`注意代码质量`（空话）
- 正例：`tests/e2e/setup.ts 依赖本地 5432 端口的 postgres，Docker 未起时 e2e 会超时 5 分钟才报错——本会话因此浪费时间，先启动 docker-compose up -d db`

## 增量交接

第 2 轮及以后的交接：

1. 读旧 HANDOFF.md，继承仍有效的背景/决策/约束（原样搬运，不重述）。
2. 已完成项从「任务规划」移入「当前进度」✅ 区。
3. 元数据表更新时间戳，`交接轮次` 标注 `第 N 轮（含第 1..N-1 轮继承要点）`。
4. 整体覆盖写入，不保留旧文件副本。

## 篇幅控制

| 情况 | 处理 |
|---|---|
| git diff > 200 行 | 存 `attachments/git-diff.patch`，正文第 3 节引用并概述改动要点 |
| 大文件摘录 | 截取相关区段（含行号标记）存 attachments，正文给路径 |
| 会话很长 | 只提炼与本任务直接相关的内容；闲聊/已废弃的方案丢弃 |
